# Database Schema: Terpa Web

This document provides an overview of the database structure for Terpa Web, primarily managed through Prisma ORM and utilizing a PostgreSQL 16 database.

## 1. Prisma ORM

Terpa Web utilizes [Prisma](https://www.prisma.io/) as its Object-Relational Mapper (ORM) with a **PostgreSQL 16** database. Prisma simplifies database access with a type-safe client and manages schema migrations.

- **Schema Definition:** The database schema is defined in `prisma/schema.prisma`. This file is the single source of truth for database models, their fields, types, relations, and any database-specific configurations (like indexes or constraints). The `datasource db` block specifies `provider = "postgresql"`.
- **Prisma Client:** A type-safe database client is generated by Prisma based on the schema definition. This client is typically instantiated in `lib/prisma.ts` and used throughout the application (especially in Server Actions and API Routes) to interact with the database.
- **Migrations:** Prisma Migrate (`npx prisma migrate dev` or `npx prisma migrate deploy`) is used to evolve the database schema over time and keep it synchronized with the `schema.prisma` file. Migration files are stored in the `prisma/migrations/` directory.

## 2. Key Data Models

The following is a summary of the core data models defined in `prisma/schema.prisma`. For complete details, always refer to the schema file itself.

### Core Entities

- **`User`**: Represents application users.
  - Key Fields: `id`, `email` (unique), `firstName`, `lastName`, `role` (`UserRole` enum: `ADMIN`, `CUSTOMER`).
  - Authentication: Related to `UserPassword` (for password hash) and `UserTOTP` (for 2FA).
  - Relations: `TeamMember` (memberships), `UserMachine` (assigned machines), `Product` (created products), `Invoice` (approved/rejected/cancelled).
- **`Team`**: Represents teams or organizations.
  - Key Fields: `id`, `slug` (unique), `name`, `legalEntityType`, `onboardingCompleted`.
  - Relations: `TeamMember` (members), `Machine` (owned machines), `Product` (team products), `Invoice`, `TeamDocument`, `ApiKeys`, `Route`, `Terminal` (assigned terminals for administrative organization).
- **`Machine`**: Represents physical vending or service machines.
  - Key Fields: `id`, `name`, `teamId`, `terminalSerialNumber` (unique), `protocol` (`MachineProtocol` enum: `DEX`, `MDB`), `isEnabled`, `activeUntilDate`.
  - Relations: `Team`, `User` (creator), `Sale`, `DexReport`, `MachineSpiral`, `MachinePicklist`, `Incident`, `UserMachine` (users assigned to machine), `InvoiceItem`.
- **`Terminal`**: Represents payment terminals associated with machines.
  - Key Fields: `id`, `serialNumber` (unique), `pharosTerminalCode`, `type` (`TerminalType` enum: `VENDING`, `PARKING`), `flowType` (`TerminalFlowType`), `teamId` (optional).
  - Relations: `Team` (optional, for administrative organization).
  - Note: Terminals can optionally be assigned to teams for administrative purposes. This assignment does not affect terminal functionality but provides organizational benefits for multi-team environments.
- **`Product`**: Represents products available for sale or inventory.
  - Key Fields: `id`, `name`, `priceCents`, `teamId`, `sku`.
  - Relations: `Team`, `User` (creator), `Sale`, `MachineSpiral`.

### Operational Entities

- **`Sale`**: Records sales transactions.
  - Key Fields: `id`, `machineId`, `type` (`SaleType` enum), `machineProductCost`, `paymentMethod` (`PaymentMethod` enum).
  - Relations: `Machine`, `Product`.
- **`Incident`**: Tracks issues or incidents related to machines.
  - Key Fields: `id`, `machineId`, `message`, `resolvedAt`, `resolvedByUserId`.
  - Relations: `Machine`.
- **`MachineSpiral`**: Manages product inventory within specific spirals/slots of a machine.
  - Key Fields: `id`, `machineId`, `machineCode` (unique per machine), `productId`, `maxCapacity`, `currentCount`.
  - Relations: `Machine`, `Product`, `PicklistItem`.
- **`MachinePicklist` & `PicklistItem`**: Manage restocking lists for machines.
  - `MachinePicklist`: `id`, `machineId`, `fulfilledAt`. Relations: `Machine`, `PicklistItem`.
  - `PicklistItem`: `id`, `picklistId`, `machineSpiralId`, `quantity`. Relations: `MachinePicklist`, `MachineSpiral`.
- **`MachineReconciliation`**: Records cash box reconciliations for machines.
  - Key Fields: `id`, `machineId`, `cashBoxValueCents`, `reconciliationValueCents`.
  - Relations: `Machine`, `User` (creator).
- **`Route` & `RouteMachine`**: Define service routes and assign machines to them.
  - `Route`: `id`, `name`, `teamId`. Relations: `Team`, `RouteMachine`.
  - `RouteMachine`: `routeId`, `machineId` (composite ID). Relations: `Route`, `Machine`.

### Billing & Finance

- **`Invoice`**: Manages billing invoices for teams.
  - Key Fields: `id`, `teamId`, `status` (`InvoiceStatus` enum), `totalPriceCents`, `paymentMethod` (`InvoicePaymentMethod` enum).
  - Relations: `Team`, `User` (approver/rejecter/canceller), `InvoiceItem`.
- **`InvoiceItem`**: Line items for an invoice, typically representing machine service fees.
  - Key Fields: `id`, `invoiceId`, `machineId`, `priceCents`, `startDate`, `endDate`.
  - Relations: `Invoice`, `Machine`.
- **`ExchangeRateHistory`**: Stores historical exchange rates.
  - Key Fields: `id`, `fromCurrency`, `toCurrency`, `rate`, `createdAt`.

### Supporting Models & Enums

- **Authentication Support**:
  - `UserPassword`: Stores hashed passwords for users.
  - `PasswordResetToken`: Manages tokens for password reset functionality.
  - `UserTOTP`: Manages Time-based One-Time Password (TOTP) secrets for 2FA.
- **Team Support**:
  - `TeamDocument`: Stores documents related to a team (e.g., legal proofs).
  - `TeamBusinessActivity`: Specifies business activities of a team.
  - `TeamMember`: Join table for user memberships in teams, defining roles (`TeamMemberRole` enum).
  - `TeamOnboardingTask`: Tracks the completion of onboarding tasks for a team.
  - `TeamOnboardingTaskHistory`: Logs changes to onboarding tasks.
- **Machine Support**:
  - `UserMachine`: Join table linking users to machines they are associated with.
  - `DexReport`: Stores DEX (Data Exchange) reports from machines.
- **API Keys**:
  - `ApiKeys`: Manages API keys for teams.

### Enums

The schema defines several enums to constrain field values:

- `UserRole`: `ADMIN`, `CUSTOMER`
- `LegalEntityType`: `PERSONA_FISICA`, `PERSONA_MORAL`
- `BusinessActivityType`: `FOOD_AND_BEVERAGES`, `RETAIL`, etc.
- `TeamDocumentType`: `BUSINESS_OPERATION_PROOF`, `SIGNED_CONTRACT`, etc.
- `TeamMemberRole`: `OWNER`, `OPERATOR`
- `MachineProtocol`: `DEX`, `MDB`
- `TerminalFlowType`: `A`, `B`, `C`
- `TerminalLanguage`: `ES`, `EN`
- `TerminalType`: `VENDING`, `PARKING`
- `PaymentMethod`: `CASH`, `CARD`, `FREE`, `REMOTE`
- `SaleType`: `PRODUCT`, `SERVICE`, `PHONE_RECHARGE`
- `InvoiceStatus`: `PAYMENT_PENDING`, `PAYMENT_SUCCESS`, etc.
- `InvoicePaymentMethod`: `MANUAL`, `MERCADOPAGO`

**Note:** This is a summary. The actual model names, all fields, specific types, relations, and database constraints (indexes, unique constraints, etc.) should be verified by inspecting the `prisma/schema.prisma` file.

## 3. Relationships

The models above would have various relationships defined in `prisma/schema.prisma`:

- **One-to-Many:** e.g., `User` to many `Team` (if a user can own multiple teams), `Team` to many `Machine`.
- **Many-to-Many:** e.g., `User` to `Team` (for team memberships, possibly via an explicit join table like `TeamMember`). `Route` to `Machine`.
- **One-to-One:** e.g., `User` to `UserProfile` (if profile details are in a separate table).

Prisma handles these relationships with clear syntax in the schema file.

## 4. Data Seeding

- **Purpose:** To populate the database with initial data for development, testing, or basic setup.
- **Script:** `prisma/seed.ts` is used for this purpose. This TypeScript script is executed using `tsx` (as defined in `package.json`'s `prisma.seed` script: `npm run seed`).
- **Execution:** The seed script typically uses the Prisma Client to create records for various models (e.g., default admin user, sample teams, product categories).
- **Content:** The `seed.ts` file would contain logic to:
  1.  Connect to the database using Prisma Client.
  2.  Define seed data (e.g., arrays of objects).
  3.  Use Prisma Client's `create` or `upsert` methods to insert data.
  4.  Handle potential errors and ensure idempotency if possible (e.g., by checking if data already exists before creating).

## 5. Accessing Schema Details

To get the precise and current database schema:

1.  **Open `prisma/schema.prisma`**: This file is the definitive source for all models, fields, types, attributes (like `@id`, `@unique`, `@default`), and relations (`@relation`).
2.  **Prisma Studio (Optional)**: Prisma comes with a tool called Prisma Studio (`npx prisma studio`), which provides a GUI to view and interact with your data and schema.

Understanding the `prisma/schema.prisma` file is essential for any developer working on data-related aspects of Terpa Web.

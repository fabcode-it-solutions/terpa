# Directory Structure: Terpa Web

This document outlines the main directories and their purposes within the Terpa Web project. Understanding this structure is key to navigating the codebase and comprehending its organization.

## Root Level Files

Key configuration and project files at the root of the repository:

- **`.env.example`**: Example environment variables. Copy to `.env` (gitignored) for local development.
- **`.eslintrc.json`**: ESLint configuration for code linting.
- **`.gitignore`**: Specifies files and directories ignored by Git.
- **`components.json`**: Likely configuration for Shadcn/UI, defining UI component settings.
- **`instrumentation.ts`**: Next.js file for OpenTelemetry and other performance monitoring instrumentation.
- **`next.config.mjs`**: Next.js main configuration file.
- **`package-lock.json`**: Records exact dependency versions for reproducible builds.
- **`package.json`**: Project manifest: metadata, dependencies, and npm scripts.
- **`postcss.config.mjs`**: PostCSS configuration, often used with Tailwind CSS.
- **`README.md`**: Main project README, typically containing a brief overview and setup instructions.
- **`sentry.client.config.ts`**: Sentry configuration for client-side error monitoring.
- **`sentry.edge.config.ts`**: Sentry configuration for Next.js Edge Functions.
- **`sentry.server.config.ts`**: Sentry configuration for server-side error monitoring.
- **`tailwind.config.ts`**: Tailwind CSS configuration file.
- **`tsconfig.json`**: TypeScript compiler configuration.

## Core Application Directories

- **`actions/`**:

  - **Purpose**: Contains server-side logic, primarily Next.js Server Actions. These files encapsulate business logic related to specific domains (e.g., `billing.ts`, `user.ts`, `machine.ts`).
  - **Key Files**: `billing.ts`, `incident.ts`, `inventory.ts`, `machine.ts`, `product.ts`, `route.ts`, `team.ts`, `terminal.ts`, `user.ts`.

- **`app/`**:

  - **Purpose**: The heart of the Next.js application, utilizing the App Router paradigm. Contains pages, layouts, API routes, and global application files.
  - **Root App Files**:
    - `favicon.ico`: Application favicon.
    - `global-error.tsx`: Defines a global error boundary.
    - `globals.css`: Global CSS styles.
    - `layout.tsx`: The root layout component for the entire application.
    - `page.tsx`: The component for the application's homepage (`/`).
  - **Subdirectories**:
    - `admin/`: Admin-specific section, including layouts, pages, and feature-specific subdirectories (e.g., `incidents/`, `machines/`, `invoices/`).
    - `api/`: Houses API route handlers (e.g., `dex/`, `team/`, `terminal/`, `v1/`, `webhooks/`).
    - `auth/`: Authentication-related pages and layouts (sign-in, sign-up, 2FA, password reset).
    - `health/`: Health check endpoint (`route.ts`).
    - `manifest.webmanifest/`: Web app manifest for PWA features.
    - `profile/`: User profile pages.
    - `team/`: Team management pages (create, list, view specific team).

- **`components/`**:

  - **Purpose**: Reusable UI components, promoting modularity and consistency.
  - **Structure**:
    - Shared/common components (e.g., `search-box.tsx`, `timestamp.tsx`).
    - Domain-specific subdirectories (e.g., `admin/`, `billing/`, `dashboard/`, `inventory/`, `machine/`, `product/`, `route/`).
    - `ui/`: Base UI components, likely from Shadcn/UI or custom-built primitives.

- **`lib/`**:

  - **Purpose**: Utility functions, helper modules, core logic, and third-party service integrations.
  - **Key Files**: `api.ts` (API helpers), `auth.ts` (auth logic), `bullmq.ts` (BullMQ setup), `constants.ts`, `currency.ts`, `date-utils.ts`, `env.ts` (env var management), `format.ts`, `mercadopago.ts` (MercadoPago SDK), `prisma.ts` (Prisma client), `redis.ts` (Redis client), `session.ts`, `utils.ts`, `whatsapp.ts`.
  - `api/`: Sub-directory for API-specific library code.

- **`loaders/`**:

  - **Purpose**: Data-loading functions, likely used with Next.js Server Components or for fetching data for pages/components prior to rendering.
  - **Key Files**: `dashboard.ts`, `machine.ts`, `product.ts`, `team.ts`.

- **`prisma/`**:

  - **Purpose**: Database-related files, managed by Prisma ORM.
  - **Key Files**:
    - `schema.prisma`: The main Prisma schema defining database models, relations, and data sources.
    - `seed.ts`: Script for seeding the database with initial/test data.
    - `migrations/`: Directory containing database migration files generated by Prisma Migrate.

- **`public/`**:

  - **Purpose**: Static assets directly served by the web server (e.g., images, icons, fonts).
  - **Key Files/Dirs**: `favicon.ico` (also in `app/`), `logo-black.svg`, `logo-white.svg`, `icons/`.

- **`service/`**:

  - **Purpose**: Contains service layer logic, often for interacting with external APIs or encapsulating complex business operations that don't fit neatly into Server Actions or API routes.
  - **Key Files**: `dex.ts`, `mailer.ts` (email sending), `pharos.ts` (purpose to be determined, possibly an internal service or specific integration).

- **`types/`**:

  - **Purpose**: Custom TypeScript type definitions used throughout the application.
  - **Key Files**: `admin.ts` (types specific to the admin section), potentially others for different domains.

- **`validation/`**:
  - **Purpose**: Zod schemas for data validation, ensuring data integrity for forms, API requests, and server actions.
  - **Key Files**: Schemas organized by domain (e.g., `auth.ts`, `billing.ts`, `machine.ts`, `product.ts`).

## Documentation Directory

- **`docs/`**:
  - **Purpose**: Contains all project documentation, including this file. Structured for clarity and ease of navigation. (Refer to `docs/README.md` for its internal structure).

This directory structure promotes a separation of concerns, making the codebase more organized, maintainable, and scalable.
